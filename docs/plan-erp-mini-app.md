# План мини-эпа для ERP-расчета

## Цель

Переделать демонстрационный экран расчета в клиентский мини-эп: человек сам вводит данные объекта, получает предварительную смету через headless ERP-расчет и оставляет контакты для дальнейшего замера.

## Что меняется

- Первый шаг становится клиентским: имя, телефон, адрес объекта, удобный способ связи, комментарий.
- Расчетные шаги остаются прежними: параметры квартиры, площади, работы, предварительная смета, график, материалы.
- CTA "Оставить заявку" больше не является пустой заглушкой: он проверяет имя и телефон и собирает карточку заявки на экране.
- Тексты убирают ощущение мокапа: не пишем про перенос сценария, technical ids, API или внутренние endpoint-слова.

## Граница ERP

- ERP уже используется как headless backend для расчета сметы через server-side маршрут `POST /api/repair-estimate/calculate`.
- `GIGMA_APP_TOKEN` остается только на сервере.
- Контракт создания заявки в ERP в проекте не найден и не был передан.
- Поэтому персональные данные клиента пока не отправляются в ERP автоматически. Мини-эп готовит заявку на экране, а реальную отправку нужно подключить отдельным server-side route, когда будет известен путь и формат backend-заявки.

## Что трогаем

- `src/routes/+page.svelte` — клиентский мини-эп, шаг клиента, заявка, тексты.
- `src/lib/repairFlow.ts` — добавление шага "Клиент" в общий flow.
- `src/routes/+layout.svelte` — человекочитаемое название приложения.
- `README.md` — описание нового клиентского сценария.

## Не делаем сейчас

- Не придумываем endpoint отправки заявки в ERP.
- Не храним заявки локально.
- Не отправляем имя, телефон или адрес в расчетный endpoint, потому что расчету они не нужны.
- Не расширяем сценарии beyond MVP "Санузел под плитку".

## Проверки

- `npm run build`.
- `npm run check` с фиксацией известных старых ошибок, если они останутся.
- Browser smoke на `http://127.0.0.1:5173/`:
  - заполнить имя и телефон;
  - пройти расчет 40 м² / 2.7 м / санузел 4 м²;
  - увидеть суммы `81 320`, `12 843`, `94 163`;
  - нажать "Оставить заявку" и увидеть карточку заявки с данными клиента.
- Проверить, что токен и technical mapping не попали в client bundle.

## Ревью плана

- Product: мини-эп собирает данные клиента, но не обещает отправку в ERP без контракта.
- Security: персональные данные не отправляются в неизвестный backend, токен не уходит в браузер.
- UX: первый шаг стал клиентским, CTA дает понятный результат вместо фразы "форма подключается отдельно".
